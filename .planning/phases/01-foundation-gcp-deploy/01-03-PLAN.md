<task type="auto">
  <name>Task 2: Email-code sign-in → Firebase custom token</name>
  <files>apps/api/src/routes/v1/auth/email.ts, apps/api/src/services/email-codes.ts, apps/api/src/services/email-sender.ts, packages/db/src/repos/email-codes.ts, apps/api/test/email-auth.test.ts</files>
  <read_first>01-CONTEXT.md D-04, D-05; 01-RESEARCH.md finding 1</read_first>
  <action>
- `POST /v1/auth/email/start` {email}:
  - lowercase and trim the email
  - generate a 6-digit code with `crypto.randomInt`
  - salt = 16 random bytes; store `sha256(salt+code)`, expires_at = now+10min, and the IP
  - enforce 3 starts / 15 min per email **and** per IP (count rows), returning 429 `{error:"too_many_requests"}`
  - send via `EmailSender.send({to, subject:"Your Koach code", text})`; text: "Your Koach code is 123456. It expires in 10 minutes."
  - always return 204, so the endpoint never reveals whether the email exists
  - if `EMAIL_DEV_ECHO=1` and APP_ENV=dev, log `{msg:"dev_email_code", email, code}`
- `ResendEmailSender` uses fetch to `https://api.resend.com/emails` with the Bearer key. In dev the sender is `onboarding@resend.dev`; the sender is configurable.
- `POST /v1/auth/email/verify` {email, code}:
  - find the latest unexpired code; increment attempts
  - attempts > 5 → 429
  - compare hashes with `timingSafeEqual`
  - on success: delete the code row, uid = `email:${sha256(email)}` (stable, deterministic), call `createCustomToken(uid, {email})`, upsert the users row with the email, return `EmailVerifyResponse`
  - wrong code → 400 `{error:"invalid_code"}`
- Tests: hash-only storage (grep the row for the plaintext code fails), expiry, attempt limit, rate limits, success burns the code, and a token is returned via the fake `createCustomToken`.
  </action>

  <acceptance_criteria>

    - No column in email_codes stores the plaintext code (test asserts)
    - Tests cover: 429 on 4th start within 15 min, 429 after 5 wrong attempts, 400 invalid code, expired code rejected, success returns customToken
  </acceptance_criteria>
