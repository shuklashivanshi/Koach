<objective>
Make "recording a choice adds the optional to the plan with a coverage outline" (OPT-04, D-05) actually work end to end, and finish the API the explorer needs (personal fit, re-openable ranking).

Purpose: the planner already adds a chosen optional's topics as Learn candidates, but the path stops there. Tapping such a Learn task calls GET /v1/learn/:nodeId, which only opens nodes of kind `node`, so every optional unit answers 404 and the app shows "Couldn't reach the library". Due reviews for optional units show the raw node id as their title because the planner's title map only knows GS nodes. There is no coverage outline anywhere, the choice response cannot tell the app when the optional joins the plan, and there are no planner tests for the Prelims pause. The explorer also has no "your fit" even though the quiz answers are stored.

Output: working optional Learn sessions and review titles, planner guard tests, the outline and choice-result endpoints, and personal-fit endpoints.

What already exists (do not redo): `plannerInputs` in apps/api/src/services/study.ts adds the chosen optional's topics as Mains-only Learn candidates (90 min, prerequisite chain, priority below GS); `eligibleForLearn` excludes non-Prelims nodes in the Prelims-intensive phase (so the pause already works, but is untested); `recordChoice` saves slug, reasons, decided-at; `GET /v1/optionals/status`; the decision nudge when 14 or fewer days remain. Phase 4 planner and study code are live and tested (apps/api/test/study.test.ts, packages/planner).
</objective>
